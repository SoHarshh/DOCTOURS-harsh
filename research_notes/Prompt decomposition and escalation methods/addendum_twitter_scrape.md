## 3. Confirmations

## 4. Contradictions

**C1. Re-route every message vs. pin the domain.**
Ours (routing section, shortlist #2): "re-route on every message so a wrong route lasts one turn", citing Decagon re-running intent extraction "with each new message". Scrape (K1, DoorDash): "The Orchestrator routes each turn and pins follow-up turns to the chosen agent to avoid a routing call. When the domain agent sees an out-of-scope message, it returns control and the Orchestrator reroutes within the same turn" — and "inside each domain, skills load only the relevant instructions per turn."
Resolution: not a real conflict; they operate at different levels. DoorDash pins the *domain* (our product line, which is already a field on the patient record) and still selects *skills per turn*. Keep per-message module routing; read product from the record and never route it. Both sources are production vendors; ours is directly about module selection, so no change to the shortlist beyond wording.

**C2. "Unclear" → restricted bundle vs. fail open to the full set.**
Ours: the "unclear" label maps to "a general bundle whose only write tool is hand off". Scrape (B7, Fin): selectors "fail open: the full set passes on error or timeout ... never an empty one", and its shortlist says "errors, low confidence or 'none' fall back to the full module set".
Resolution: Fin's fail-open is for selector *infrastructure* failure (error/timeout), measured in production; our restricted bundle is for *semantic* ambiguity and is safer for a bot with money and safety rules (the scrape itself warns fail-open "brings back the monolith's cost on the fallback path"). Adopt both: semantic "unclear" → our restricted bundle; router exception/timeout → default bundle + shared core, never an empty set, logged `router:error`. Fin's evidence is stronger on the infra path; ours on the semantic path.

**C3. Numbered precedence lines in the prompt as a "cheap backstop".**
Scrape (C2, TRY IF TIME): "It is cheap as a backstop, but the testable version is C3." Ours (Surprise 1): "Precedence numbers inside the prompt are the one approach with measured negative evidence" (IHEval priority sentence: GPT-4o 70.0 → 67.2, Mistral-Large 29.4 → 28.3; Wallace's numeric-level prompt "performed much worse").
Resolution: ours is stronger; the scrape's own C2 sources (Control Illusion) show stated priorities are overridden by model biases, and it reports no number in favour. Do not add precedence prose; keep forbid-first ordering within modules (Surprise 15) and the code resolver.

**C4. Model-self-cited `applied_rules` rated TRY FIRST.**
Scrape (C4, Ev 2): "nearly free and directly addresses 2 and 7 ... treat them as a hint." Ours (Surprise 13, Turpin et al.): "model self-reported `applied_rule_ids` are hints, not evidence."
Resolution: same epistemics, different priority. The field costs one schema change (which invalidates the grammar/prompt cache once, Surprise 8). Add it as a filterable hint only after shortlist items 1–5 are done; never let it count as attribution.

**C5. Embedding router worth trying vs. does not earn its dependency.**
Scrape (B2, TRY IF TIME): Thumbtack, "the embeddings approach has 49.5% higher accuracy than the prompting approach ... 14 and 81 times faster ... up to 10 times cheaper" (https://arxiv.org/abs/2504.04277). Ours (routing section): MiniLM kNN 75.1% on CLINC150 full / 64.2% five-shot, below TF-IDF (Rodrigues & Vas); an "Always-Mid" baseline matched the Aurelio router on 3/4 benchmarks (Kumar & Saminathan); no Anthropic embeddings API.
Resolution: ours is stronger for our constraints. Thumbtack trained a classifier on embeddings with a labelled corpus; we have ~65 cases, no training set and no embeddings vendor. Keep skip.

**C6. Temperature for the suite.**
Scrape (G3 risks): "At temperature 0 a Haiku-class model may vary little; measure once anyway." Ours (Surprise 10, Miller): "sampling temperature should never be lowered to fake stability."
Resolution: ours is a methodological rule from a primary source; the scrape's line is a hedge. Run the suite at the production temperature and report pass^3.

**C7. Trace schema and OTel version.**
Ours: cites core-repo semconv v1.37.0 and proposes a custom `GUARDRAIL`-kind child span per validator. Scrape (F1): `gen_ai.*` was deprecated in the core repo at v1.42.0 (2026-06-12) and moved to `semantic-conventions-genai` (still Development, no release); `gen_ai.evaluation.result` with `gen_ai.evaluation.score.label` / value / explanation "is the standard slot for 'which check failed'".
Resolution: the scrape is more current (**verify**). Pin a commit of the genai repo, emit validator verdicts as evaluation-result events, keep our custom `coordinator.rules.loaded/skipped` attributes. Both agree there is no standard field for "which instructions were loaded".

**C8. Cost framing: "not the lever" vs. "biggest risk".**
Ours (Surprise 6): "Cost is not the lever, and trimming can break caching." Scrape (executive summary): "a cached monolith could be cheaper per turn than an uncached routed build. Measure both" — and its shortlist adds a "monolith + caching" baseline arm.
Resolution: same facts, but the scrape turns it into a concrete harness arm that our shortlist lacks. Add the cached-monolith arm (and the distilled-monolith arm from N7).

**C9. Domain agents at 2+ domains.**
Ours (Surprise 9): "Sub-agents do not belong on the reply path." Scrape (J4, TRY IF TIME "for domain 2"): on τ-bench retail with distractor domains "a single agent falls off sharply at 2+ distractor domains, while swarm and supervisor stay flat."
Resolution: not a conflict today. The LangChain single agent carried every domain's 19 tools and wiki at once; code-scoped assembly loads one product's modules. Treat J4 as the fallback if the confusability check (N36) fails at domain 3+, not as part of the plan.

**C10. Precedence failure rate: 40–48% vs 27.9%.**
Scrape: "Prompt-level rule precedence holds only about 40-48% of the time under conflict" (IHEval best open-source model; ManyIH frontier ~40%). Ours: Claude-3 Haiku 27.9% on IHEval. Not a contradiction; ours is the model-relevant cut of the same benchmark. Cite ours.

## 6. Recommended changes to our shortlist

1. **Shortlist #1 (harness): add two baseline arms, ~0.5 h.** (a) Monolith + prompt caching, so the routed build is compared against the cached monolith on cost (scrape I1 risk; C8). (b) "Distilled monolith": a ≤ 2k-token core with no routing (claude.dev −80%, Vercel −80%; N7). If (b) matches the routed build on the 65, routing is optional for domain 1 and the hours go to validators and escalation.
2. **Insert a step between #1 and #2: monolith error analysis, 0.5–1 h.** Run the monolith on the 65, tag each failure with the policy module it belongs to; the tags become the module map and the validator list (Hamel/Shankar FAQ; N24).
3. **Shortlist #2 (modules + router):** cap loaded modules at 3 per turn and keep them compact and hand-written (SkillsBench; N3); add `route_description`, `scope_allowed`, `scope_forbidden`, `tools` to module frontmatter and show the classifier only `id + route_description` (Agentforce/Copilot; N39); put 2–3 static examples per route in the classifier prefix (N9); review descriptions pairwise for confusability (N36); read product from the patient record instead of routing it, keep per-message module routing (C1); add the infra fail-open path: router exception/timeout → default bundle + shared core, never empty, logged (N6, C2).
4. **Shortlist #3 (validators):** add a claims-vs-receipts validator for handoff / booking / "sent" / "done" language with no matching tool call this turn (False Success 45–48%, judges cannot catch it; N15); code-fix format-only failures (markdown, length) without a retry and keep the single retry for content failures (Guardrails FIX, PCN; N16, N17); cite NabaOS for the set-membership check.
5. **Shortlist #4 (escalation):** add `validator_budget_exhausted` and `cannot_do_intent` to the hard-trigger `reason` enum (12-factor; ToolGuards/DoorDash; N10, N13).
6. **Shortlist #5 (rule registry):** enforce at the tool boundary (wrap the 14 tools), not only on reply text; cite ToolGuards' pass^k alongside PCAS (N10). Do not add precedence prose to the prompt (C3).
7. **Trace:** pin a commit of `semantic-conventions-genai`, emit validator verdicts as `gen_ai.evaluation.result` events, keep `coordinator.rules.loaded/skipped` as custom attributes (N20, C7). Add `applied_rules` as a hint only after items 1–5 (C4).

9. **Deferred GEPA pass:** follow Decagon's recipe (20–50 train cases, held-out split, Sonnet-class reflector, 1,500-character cap) rather than a default `light` run (N29).
